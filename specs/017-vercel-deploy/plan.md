# Implementation Plan: Vercel Deployment

Source spec: [spec.md](./spec.md)

Swaps the SQLite adapter to libSQL (`file:` locally, `libsql://` Turso in production), adds an idempotent `scripts/migrate.ts` for Turso, derives WebAuthn RP settings from Vercel env vars, and documents the few manual deploy steps. Schema, models, migrations and UI do not change.

## Technical context

- Today: `src/prisma/prismaClient.ts` uses `PrismaBetterSqlite3` with `process.env.DATABASE_URL ?? "file:./prisma/dev.db"`. `better-sqlite3` is only a transitive dependency of `@prisma/adapter-better-sqlite3` (not in `package.json`); removing the adapter removes it.
- Add `@prisma/adapter-libsql` (spec exception). It brings `@libsql/client`, imported directly by the migrate script. No other package. Verify the exported class name (`PrismaLibSql`) after install in `node_modules/@prisma/adapter-libsql`.
- Node 22.22 locally: `.ts` scripts run natively with `node` (type stripping). Rules for `scripts/`: no enums, no parameter properties, `import type` for types, explicit `.ts` extensions on relative imports. Node does **not** load `.env`; the script reads `process.env` only.
- Existing migrations contain `PRAGMA foreign_keys` / `defer_foreign_keys` lines and a RedefineTables block (`20260921162349_accounts_passkeys`). They contain no triggers and no `;` inside string literals, so statements can be split on `;` at end of line. Inside a batch transaction the `foreign_keys` PRAGMAs are no-ops; the fresh Turso database is empty, so dropping/redefining tables is safe. Future redefine-table migrations on a populated production database need manual review.
- `prisma.config.ts` reads `env("DATABASE_URL")`, so `prisma generate` (postinstall) needs `DATABASE_URL` set. Locally `.env` provides it; on Vercel the env var must exist before the first build.
- `tests/actions/globalSetup.ts` and `vitest.config.ts` `actions` project already set `DATABASE_URL=file:./prisma/test.db`. `tests/actions/setup.ts` clears tables in `beforeEach`.
- Next 16 `serverExternalPackages`: read the list of auto-externalized packages in `node_modules/next/dist/docs/` before editing `next.config.ts`.
- Passkey config lives in `src/actions/auth/config.ts` (`rpID`, `origin`, plus unrelated constants that stay).

### `src/prisma/prismaClient.ts`

```ts
import { PrismaClient } from "@/generated/prisma/client";
import { PrismaLibSql } from "@prisma/adapter-libsql";

const globalForPrisma = globalThis as unknown as { prisma?: PrismaClient };

function createClient() {
  const adapter = new PrismaLibSql({
    url: process.env.DATABASE_URL ?? "file:./prisma/dev.db",
    authToken: process.env.TURSO_AUTH_TOKEN,
  });
  return new PrismaClient({ adapter });
}

export const prisma = globalForPrisma.prisma ?? createClient();
if (process.env.NODE_ENV !== "production") globalForPrisma.prisma = prisma;
```

Keep the "server code only" header comment.

### `scripts/migrate.ts`

Exports (importable by tests) plus a CLI entry:

```ts
import { createClient } from "@libsql/client";
import { readdir, readFile } from "node:fs/promises";
import { join } from "node:path";
import { pathToFileURL } from "node:url";

export function splitStatements(sql: string): string[]   // drop `--` comment lines, split on ";" at end of line, trim, drop empties
export async function migrate(opts: {
  url: string;
  authToken?: string;
  dir: string;          // prisma/migrations
  allowFile?: boolean;
}): Promise<{ skipped: boolean; applied: string[] }>
```

- `migrate`:
  - `file:` URL and `!allowFile` → log `Skipping migrations: local database is managed by Prisma Migrate.` and return `{ skipped: true, applied: [] }` (no connection opened).
  - `createClient({ url, authToken })`; `CREATE TABLE IF NOT EXISTS _migrations (name TEXT NOT NULL PRIMARY KEY, appliedAt TEXT NOT NULL)`.
  - List directories in `dir` (skip `migration_lock.toml`), sort by name; skip names already in `_migrations`.
  - For each pending migration: `client.batch([...splitStatements(sql).map(sql => ({ sql, args: [] })), { sql: "INSERT INTO _migrations (name, appliedAt) VALUES (?, ?)", args: [name, new Date().toISOString()] }], "write")`. `batch` is one transaction, so a failure rolls back that migration and its record; rethrow.
  - Close the client in `finally`.
- CLI (bottom of file): run only when `import.meta.url === pathToFileURL(process.argv[1]).href`.
  - `url = process.env.DATABASE_URL ?? "file:./prisma/dev.db"`; `allowFile = process.argv.includes("--allow-file")`.
  - If `process.env.VERCEL` is set and `url` does not start with `libsql:`: print `DATABASE_URL must be a libsql:// URL on Vercel.` and exit 1 (prevents a silently broken deploy).
  - Log each applied migration; on any error print it and `process.exit(1)`.
- Relative imports (none needed) would need `.ts` extensions.

### `tests/actions/scripts/migrate/migrate.test.ts`

Lives under the `actions` project glob. Imports `migrate` and `splitStatements` from `../../../../scripts/migrate.ts`. Uses `mkdtemp` under `os.tmpdir()` for a fake `migrations/` folder and a temp `file:` database; never `test.db`, `dev.db` or Turso. Cases:

- Two migrations apply in name order and are recorded in `_migrations`.
- Second run applies nothing (`applied: []`).
- A migration with a failing statement rejects, leaves none of its statements applied, and does not record it.
- `file:` URL without `allowFile` returns `{ skipped: true }` and creates no database file.
- `splitStatements` ignores comment lines and trailing empty statements.

## Implementation order

1. Install `@prisma/adapter-libsql`, uninstall `@prisma/adapter-better-sqlite3`; add scripts and `engines` to `package.json`.
2. Rewrite `src/prisma/prismaClient.ts`; run `npm run prisma:generate` and commit the regenerated output only if it changed.
3. Update `next.config.ts` and `vitest.config.ts` (after reading the Next docs).
4. Run `npm test` and `npm run test:e2e` to confirm local SQLite files still work through libSQL before going further.
5. Write `scripts/migrate.ts` and `tests/actions/scripts/migrate/migrate.test.ts`.
6. Update `src/actions/auth/config.ts`.
7. Update `.env.example`, `README.md`, `AGENTS.md`.
8. Run `npm run build` locally (must skip migrations and not modify `prisma/dev.db`), then the full test suite.
