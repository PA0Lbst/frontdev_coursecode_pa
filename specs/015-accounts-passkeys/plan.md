# Implementation Plan: Accounts with Passkeys

Source spec: [spec.md](./spec.md)

Adds `User`/`Passkey`/`AuthSession`/`AuthChallenge`, passkey-only registration and sign-in through Server Actions, cookie sessions, per-user ownership on every workout action, `/sign-in` and `/account` pages, and a signed-in Header. Existing workouts are wiped by the migration.

## Technical context

- Add `@simplewebauthn/server` and `@simplewebauthn/browser` (spec exception). No other package. Do not add a CBOR/JWT/session library.
- Next 16: `cookies()` from `next/headers` is **async** (`await cookies()`); it may set/delete cookies only inside Server Actions. Read `node_modules/next/dist/docs/01-app/03-api-reference/04-functions/cookies.md` and `redirect` docs before coding.
- Prisma 7 + SQLite: no enums, use `String` (typed as a TS union in code); `Bytes` maps to `Uint8Array` (wrap with `Buffer.from` / `new Uint8Array` at the SimpleWebAuthn boundary). Generated client in `src/generated/prisma` is regenerated by `npm run prisma:generate`, never hand-edited.
- Actions: `src/actions/{resource}/{actionName}/{actionName}.ts`, `"use server"`, one async named export. Shared non-action helpers go in `src/actions/auth/helpers.ts` (no `"use server"`).
- Tests: `globalSetup` runs `prisma migrate deploy` on `prisma/test.db`; `setup.ts` clears tables before each test; `next/headers` is not available in vitest node, so it is mocked in `setup.ts`.
- `PageTemplate` renders `Header` (currently a static `h1`); `WorkoutListPage`, `WorkoutPage` wrap themselves in `PageTemplate`.

## Schema and migration

```prisma
model User {
  id          Int              @id @default(autoincrement())
  username    String           @unique
  createdAt   DateTime         @default(now())
  passkeys    Passkey[]
  authSessions AuthSession[]
  workouts    WorkoutSession[]
}
model Passkey {
  id         String   @id            // base64url credential id
  userId     Int
  user       User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  publicKey  Bytes
  counter    Int
  transports String?                 // JSON array
  label      String?
  createdAt  DateTime @default(now())
}
model AuthSession {
  id        Int      @id @default(autoincrement())
  userId    Int
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  tokenHash String   @unique
  expiresAt DateTime
  createdAt DateTime @default(now())
}
model AuthChallenge {
  id        Int      @id @default(autoincrement())
  challenge String
  purpose   String   // "register" | "authenticate" | "add"
  username  String?  // register: the requested username
  userId    Int?     // add: the signed-in user
  expiresAt DateTime
}
// WorkoutSession: add `userId Int` + `user User @relation(..., onDelete: Cascade)`
```

- Generate with `npm run prisma:migrate -- --create-only --name accounts_passkeys`, then **prepend** `DELETE FROM "WorkoutSet"; DELETE FROM "WorkoutSession";` to `migration.sql` (SQLite cannot add a required column to a non-empty table), then `npm run prisma:migrate` and `npm run prisma:generate`.
- This wipes `prisma/dev.db` workouts (chosen). `test.db` is migrated by `globalSetup`.

## `src/data/username.ts`

- `normalizeUsername(s)` → `s.trim().toLowerCase()`; `isValidUsername(s)` → `/^[a-z0-9_]{3,20}$/` on the normalized value. Used by client (SignInPage) and server.

## `src/actions/auth/config.ts` / `helpers.ts`

- `config.ts`: `rpID = process.env.WEBAUTHN_RP_ID ?? "localhost"`, `origin = process.env.WEBAUTHN_ORIGIN ?? "http://localhost:3000"`, `rpName = "Workoutish"`, `SESSION_COOKIE = "session"`, `SESSION_DAYS = 30`, `CHALLENGE_MINUTES = 5`.
- `helpers.ts` (no `"use server"`):
  - `hashToken(t)` → SHA-256 hex (`node:crypto`).
  - `createSessionCookie(userId)`: random 32 bytes base64url, insert `AuthSession` (hash only), `(await cookies()).set(SESSION_COOKIE, token, { httpOnly: true, secure: NODE_ENV === "production", sameSite: "lax", path: "/", expires })`.
  - `requireUser()`: `getCurrentUser()` or `throw new Error("Unauthorized")`; returns `User`.
  - `consumeChallenge(id, purpose)`: `findUnique` → throw `"Invalid challenge"` if missing, wrong purpose or expired → `delete` (single use, deleted even on later verify failure) → return the row.

## Auth actions

- `getCurrentUser()`: read cookie → `hashToken` → `AuthSession` with `expiresAt > now` and `include: { user: true }` → `User | null`. Returns only `{ id, username, createdAt }`.
- `startRegistration(username)`: normalize + validate (`throw "Invalid username"`); if taken throw `new Error("That username is taken.")`; `generateRegistrationOptions({ rpName, rpID, userName, attestationType: "none", authenticatorSelection: { residentKey: "required", userVerification: "preferred" } })`; store challenge (`purpose: "register"`, `username`); return `{ challengeId, options }`.
- `finishRegistration({ challengeId, response })`: `consumeChallenge(id, "register")`; re-check username still free; `verifyRegistrationResponse({ response, expectedChallenge, expectedOrigin: origin, expectedRPID: rpID })`; `verified` else throw; in one `$transaction`: create `User`, create `Passkey` from `registrationInfo.credential` (`id`, `publicKey`, `counter`, `transports`); `createSessionCookie`; return `{ id, username }`. Unique-violation on username maps to the taken message.
- `startAuthentication()`: `generateAuthenticationOptions({ rpID, userVerification: "preferred" })` with no `allowCredentials` (discoverable); store challenge (`"authenticate"`); return `{ challengeId, options }`.
- `finishAuthentication({ challengeId, response })`: consume challenge; load `Passkey` by `response.id` (missing → generic `throw "Invalid credentials"`); `verifyAuthenticationResponse({ response, expectedChallenge, expectedOrigin, expectedRPID, credential: { id, publicKey, counter, transports } })`; not verified → throw; update `counter` to `newCounter`; `createSessionCookie`; return `{ id, username }`. Any failure throws the same generic error.
- `signOut()`: delete the `AuthSession` row for the cookie token (if any), `cookies().delete`, then `redirect("/sign-in")` from `next/navigation` (client callers get the navigation; tests assert the `NEXT_REDIRECT` throw).
- `listPasskeys()`: `requireUser`; returns `{ id, label, createdAt }[]` (never `publicKey`).
- `startAddPasskey()` / `finishAddPasskey({ challengeId, response, label? })`: like registration but `requireUser`, `purpose: "add"`, `challenge.userId = user.id` (must match on finish), `excludeCredentials` from the user's passkeys, insert `Passkey` only.
- `removePasskey(id)`: `requireUser`; passkey must belong to user else `Not found`; if user has exactly one → `throw new Error("You need at least one passkey.")`; delete; return void.
- All error messages above that the UI may show verbatim: `That username is taken.`, `You need at least one passkey.`. Everything else is shown as `Something went wrong. Try again.` on the client (never `error.message`).

## Ownership in workout actions

- Every action begins `const user = await requireUser();`.
- `createSession`: `data: { name, userId: user.id }`. `listSessions`: `where: { userId: user.id }`. `getSession(id)`: `findFirst({ where: { id, userId: user.id }, include })` → `null` for foreign/missing. `deleteSession(id)`: `findFirst` with ownership else `throw "Not found"`, then delete.
- `createSet`: session lookup by `{ id: sessionId, userId }`, missing → `throw "Not found"` (replaces `"Session not found"`; update its existing test). `updateSet` / `deleteSet`: `findFirst({ where: { id, session: { userId: user.id } } })` else `throw "Not found"`, then write.
- Clients never send a user id.

## UI

- `Header` becomes `"use client"`: optional props `username?: string`, `onSignOut?: () => Promise<void>`. When `username` is set render `<Link href="/account">{username}</Link>` and a `Sign out` `Button` (native `disabled` while pending; awaits `onSignOut`). Without `username` it renders as today, so existing tests/stories keep passing.
- `PageTemplate`: optional `username`, `onSignOut`, forwarded to `Header`. `WorkoutListPage`, `WorkoutPage`, `AccountPage`: optional `username`, `signOut` props forwarded to `PageTemplate` (`onSignOut={signOut}`).
- `SignInPage` (client): props `startRegistration`, `finishRegistration`, `startAuthentication`, `finishAuthentication`. Two sections: `Register` (label `Username`, `Input` with `autoComplete="username webauthn"`, `Create account` button) and `Sign in with passkey` button. Uses `startRegistration` / `startAuthentication` from `@simplewebauthn/browser` (imported under aliases to avoid the prop-name clash), then `router.push("/")` (`useRouter` from `next/navigation`). Validates with `isValidUsername` before calling. Unsupported check via `browserSupportsWebAuthn()` → `role="alert"` `This browser does not support passkeys.`. Aborted ceremony (`NotAllowedError`) shows the generic message. Conditional UI is optional: call `startAuthentication({ optionsJSON, useBrowserAutofill: true })` only if `browserSupportsWebAuthnAutofill()` — keep out of the first pass if it complicates tests (spec says "where supported").
- `AccountPage` (client): props `username`, `initialPasskeys`, `startAddPasskey`, `finishAddPasskey`, `removePasskey`, `signOut`. List with created date (coerce `createdAt` to `Date`), `Add a passkey`, `Remove` per row (native `disabled` while pending), copy: `Add a second passkey so you can not be locked out.` Apply results locally (append / filter), no refetch; alert per AGENTS.md except the `You need at least one passkey.` message.
- Both new pages wrap `PageTemplate`, `mx-auto w-full max-w-2xl`, 44px targets (`Button size="lg"` or the classes used in spec 014).
- Stories: `Pages/SignInPage`, `Pages/AccountPage`, `fullscreen`, `autodocs`, one `Default` with `play`; `controls.include: []` and action props hidden like `WorkoutPage`. Stories pass `fn()` props and cannot run real WebAuthn, so their `play` only checks rendering and validation errors.

## Routes

- `src/app/sign-in/page.tsx`: `force-dynamic`; `if (await getCurrentUser()) redirect("/")`; render `SignInPage` with the four ceremony actions.
- `src/app/page.tsx`, `src/app/workouts/[id]/page.tsx`, `src/app/account/page.tsx`: `const user = await getCurrentUser(); if (!user) redirect("/sign-in");` first, then existing logic; pass `username={user.username}` and `signOut`. Import `redirect` from `next/navigation`. No `proxy.ts`.

## Tests

- `tests/actions/helpers/cookieStore.ts`: exports a module-level `Map` and `resetCookies()`. `setup.ts`: `vi.mock("next/headers", () => ({ cookies: async () => ({ get: n => map.has(n) ? { name: n, value: map.get(n) } : undefined, set: (n, v) => map.set(n, v), delete: n => map.delete(n) }) }))`; `beforeEach` calls `resetCookies()` and deletes rows in order `workoutSet, workoutSession, authChallenge, authSession, passkey, user`.
- `tests/actions/helpers/auth.ts`:
  - `signInAs(username)`: create `User` + `AuthSession` via real `hashToken`, set the cookie in the store, return the user.
  - Software authenticator (Node `crypto`, ES256 P-256 keypair, a ~30-line CBOR encoder in the helper, no package): `createAttestation(options)` builds `clientDataJSON` (`type`, `challenge`, `origin: "http://localhost:3000"`), `authData` (rpIdHash, flags `UP|UV|AT`, counter, credential id, COSE key) and `fmt: "none"` attestation object; `createAssertion(options, credential)` signs `authData || sha256(clientDataJSON)`, increments counter.
- Auth action tests: `startRegistration` (taken/invalid username), `finishRegistration` (creates user + passkey + session cookie; expired/reused challenge rejected; duplicate username), `startAuthentication`/`finishAuthentication` (valid assertion signs in; wrong challenge, unknown credential, replayed counter rejected), `signOut` (`rejects` `NEXT_REDIRECT`, session row gone), `getCurrentUser` (no cookie, expired session), passkey list/add/remove (last-passkey guard, foreign passkey `Not found`).
- Update existing workout action tests: `signInAs` in each test; add cases: no session → `Unauthorized`; user B cannot `getSession` (null), `deleteSession`, `createSet`, `updateSet`, `deleteSet` on A's data (`Not found`); `listSessions` scoped.
- Components: `vi.fn()` action props, `vi.mock("@simplewebauthn/browser")` and `vi.mock("next/navigation")`. Cover: validation error, unsupported browser, success calls `router.push("/")`, generic alert on failure, `Header` sign-out shows only with `username` and disables while pending, `AccountPage` add/remove/last-passkey message.
- E2E helpers `tests/e2e/helpers/auth.ts`: `register(page, username)` sets up `context.newCDPSession(page)` → `WebAuthn.enable` → `WebAuthn.addVirtualAuthenticator` (`protocol: "ctap2"`, `transport: "internal"`, `hasResidentKey: true`, `hasUserVerification: true`, `isUserVerified: true`, `automaticPresenceSimulation: true`) then submits the register form. `tests/e2e/auth.spec.ts`: register (timestamped unique username) → `/` → create workout → `Sign out` → `/sign-in` → `Sign in with passkey` → workout visible; visiting `/` signed out redirects to `/sign-in`. `workout.spec.ts`: call `register` at the start of each test.

## Implementation order

1. Install the two packages; schema + hand-edited migration; `prisma:generate`.
2. `username.ts`, `config.ts`, `helpers.ts`, `getCurrentUser`.
3. Test infra: `setup.ts` mock, `cookieStore.ts`, `auth.ts` helper (`signInAs` first, software authenticator next).
4. Auth actions with tests: register, authenticate, `signOut`, passkey management.
5. Ownership in workout actions; update their tests.
6. `Header` / `PageTemplate` / existing pages get optional `username` + `signOut`.
7. `SignInPage`, `AccountPage` (components, stories, tests).
8. Routes: `sign-in`, `account`, guard + props on `/` and `/workouts/[id]`.
9. E2E helper, `auth.spec.ts`, update `workout.spec.ts`.

## Out of scope

- Passwords, email, SMS, magic links, OAuth, account recovery, username change, account deletion, admin roles, cross-device passkey sync.
- Rate limiting of authentication (deferred; single-use 5-minute challenges only).
- `proxy.ts` / cookie-presence redirects; Route Handlers; `revalidatePath` / `router.refresh`.
- Friends and sharing (spec 016).
